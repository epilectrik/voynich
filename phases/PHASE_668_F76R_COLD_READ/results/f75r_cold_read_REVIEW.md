## ERRORS

### E1. Total dar count is wrong (P9 section + dar distribution)

**Location:** P9 narrative ("46% of the folio's total 26 dar") and implicitly the dar distribution percentages.

**The error:** The cold read states the folio total is 26 dar. Summing from the JSON (and from the cold read's own dar distribution table): 2+1+0+0+2+3+2+5+12 = **27**, not 26. The percentage "46%" is computed from 26; the correct value is 12/27 = **44.4%**.

**Correction:** Change "total 26 dar" to "total 27 dar" and adjust the percentage to ~44%. The dar distribution table percentages should also be recomputed from denominator 27:
- P1: 2/27 = 7%
- P2: 1/27 = 4%
- P5: 2/27 = 7%
- P6: 3/27 = 11%
- P7: 2/27 = 7%
- P8: 5/27 = 19%
- P9: 12/27 = 44%

### E2. The x9 window is NOT corpus-singular (P9 section)

**Location:** P9 narrative: "This 9-token window is **corpus-singular**: no other 2-consecutive-line window in all of Currier B contains 9 or more qok-class tokens."

**The error:** C1969 explicitly states: ">=9 qok-class tokens within any 2-consecutive-line window appears on **3/82 = 3.7%** of Currier B folios (f75r L37-L38, f86v3 L1-L2, f108r L48-L49)." The x9 window is NOT corpus-singular. Two other folios (f86v3 and f108r) also reach the threshold.

C1969 further notes: "Of those three high-density folios, only f75r matches a Catalan chapter carrying explicit x9 vegades." This makes the MATCH significant, but the density pattern itself is not unique.

**Correction:** Replace the corpus-singular claim with something like: "This 9-token fire-management window occurs on only 3 of 82 Currier B folios (C1969). Of the three, only f75r matches a recipe with an explicit x9 count." The same correction should apply to the Verdict section which also calls the x9 window "corpus-singular."

### E3. P9 observation MIDDLE count disagrees with JSON

**Location:** Folio summary table, P9 row: "1 ckh, 1 cth"

**The error:** The JSON for P9 reports `"obs_middle_counts": {"ckh": 1}` -- only 1 ckh, no cth. The cold read claims "1 cth" in P9 which would be L33's `chcthedy` (atoms c.t.h.e.d.y). The `cth` pattern IS present in those atoms, so the cold read's reading is plausible, but it contradicts the JSON data that was generated by the same pipeline. Either the JSON's obs_middle detection missed this instance (possible script bug -- the atoms are inside a `ch`-prefixed token, and `cth` starts with `c` which overlaps the prefix boundary) or the cold read is over-reading.

**Correction:** Either flag this as uncertain ("1 cth, not confirmed by automated count") or investigate why the JSON missed it. The narrative in the P9 section doesn't specifically discuss this cth, so the impact is confined to the summary table and the cross-paragraph observation MIDDLE distribution table.

### E4. P6 "three dain" is factually wrong

**Location:** P6 narrative: "L26 has three `dain` ('bind material into cycle') -- loading materials for the x9 phase."

**The error:** L26 raw data: `dain`, `ol`, `sheol`, `dain`, `ol`, `qoly`, `dar`, `ady`. That is 2 `dain` + 1 `dar` = 3 da-prefix tokens, but NOT 3 `dain`. The cold read conflates the three material additions with three identical tokens.

**Correction:** "L26 has two `dain` ('bind material into cycle') and one `dar` ('add a new substance') -- three material additions loading for the x9 phase."

## OVERSTATEMENTS

### O1. "Across all 15 cold-read folios" (P7 section)

**Location:** P7: "e-depth 0.18 -- the lowest of any paragraph across all 15 cold-read folios."

**Issue:** This cold read is the template/first read in Phase 668. The claim to have compared against 15 cold-read folios is either a forward reference to planned work or based on unpublished prior analysis. As written, it makes a comparative claim that cannot be verified from the current document set.

**Recommendation:** Replace with "the lowest on this folio" or, if the 15-folio comparison is supported by separate analysis, add a citation. The internal superlative is already striking enough (0.18 vs 0.42-0.63 range) without the external comparison.

### O2. P3 narrative claims "L8 introduces the first heat-level check (chckhy)"

**Location:** P3, paragraph 2 of narrative.

**Issue:** Looking at the raw data, P1 L5 contains `ckhey` (atoms c.k.h.e.y) which also contains the `ckh` pattern. However, the JSON P1 obs_middle_counts is `{}` (empty) -- so the automated pipeline does not count L5's `ckhey` as a ckh observation MIDDLE. The cold read says P1 has zero obs MIDDLEs which is consistent with the JSON. But then calling P3's chckhy "the first heat-level check" depends on whether P1's `ckhey` counts. The JSON says no, so the claim is defensible but could be challenged.

**Recommendation:** Minor issue. Leave as-is or add "the first dedicated heat-level check token" for precision.

### O3. x9 window boundary interpretation is speculative

**Location:** P9: "Tokens 4-5 in the window (qokchdy, qokechdy on L37) include active checking (ch). These fall at the boundary between the first 4 and the subsequent 5 within the window -- the same structural boundary the recipe describes (x4 then x9, with the x9 building on the x4). The monitoring marks the transition."

**Issue:** The claim that tokens 4-5 in the window mark the "x4/x9 boundary" is interpretively attractive but structurally speculative. The recipe describes x4 followed by x9 as sequential phases, not as a single window split 4+5. The monitoring tokens at positions 4-5 could be coincidental within a dense fire-management sequence. This reads as narrative embellishment rather than structural evidence.

**Recommendation:** Downgrade the language. Instead of asserting the tokens "mark the transition," note that the ch-containing tokens appear mid-window and are "consistent with" a monitoring checkpoint, without claiming they encode the x4/x9 structural boundary.

## OMISSIONS

### M1. P1 chekar not discussed

The JSON shows `chekar_count: 1` for P1, but the cold read narrative for P1 does not mention any quality check. Looking at the raw data, L2's `chedykar` has unusual morphology -- it may or may not contain a genuine chekar. The observation MIDDLE distribution table shows P1 with 0 total obs MIDDLEs, and the P1 narrative says nothing about a chekar. If the JSON is correct, this is a quality-check token that the narrative misses; if the JSON is a false positive (substring match artifact), this should be noted.

**Recommendation:** Either explain why the JSON shows chekar_count=1 for P1 despite no obvious `chekar` token, or add a brief note acknowledging the discrepancy.

### M2. P3 chekar not discussed in observation distribution table

The JSON shows `chekar_count: 1` for P3 (L11's `chekam`). The cold read's observation distribution table doesn't include chekar as a separate row, though the folio summary table for P3 doesn't list it either. The chekar tokens appear in the Token Dictionary but aren't systematically tracked in the cross-paragraph pattern tables.

**Recommendation:** Consider adding a chekar row to the cross-paragraph observation table, or note that chekar quality checks are a separate tracking dimension from observation MIDDLEs.

### M3. No mention of C1969 or C1965 constraint references

The cold read makes corpus-singularity and counting-anchor claims that are directly addressed by C1965 (the cycle-counting idiom) and C1969 (the window-density specificity test). Neither constraint is cited. For a document that serves as the template for future cold reads, explicit constraint anchoring would strengthen the claims.

**Recommendation:** Add brief constraint citations in the x4 and x9 sections: "This 4-token identical run is corpus-singular in Currier B (C1889)" and "This 9-token density occurs on 3/82 folios (C1969); only f75r matches a recipe with explicit x9."

## OVERALL: Minor Issues

The cold read is fundamentally sound. The recipe mapping is coherent, token readings are well-grounded, and the structural patterns (e-depth arc, dar distribution, observation fade-out) are genuine. Four specific errors need correction:

1. **dar total 26 -> 27** (arithmetic error, affects percentages)
2. **x9 window NOT corpus-singular** (contradicts C1969; 3 folios reach the threshold)
3. **P9 observation MIDDLE cth unconfirmed** (JSON disagrees)
4. **P6 "three dain" -> "two dain + one dar"** (token misidentification)

None of these errors affect the overall COHERENT verdict. The recipe-folio correspondence holds: the paragraph structure tracks the recipe phases, the counting anchors are real (x4 is corpus-singular, x9 is rare at 3/82), and the thermal arc matches the physical chemistry. The errors are bookkeeping issues, not structural failures.

**Recommendation:** Correct the four errors, downgrade the x9 corpus-singularity claim to "rare (3/82)" with C1969 citation, and qualify the "15 cold-read folios" comparative claim. After these fixes, the cold read is publication-ready as the template for future reads.
